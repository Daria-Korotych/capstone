# ADR-0007: Стратегія партиційного ключа — кільце хешує таблицю і partition key, sort key не хешується

Status: Accepted

**Рішення коротко:** ключ кільця = `"{table}\x1f{pk}"`, тож усі items однієї партиції (з усіма sort key) лежать на одному шарді.

## Context

- Модель DynamoDB: partition key визначає шард, sort key впорядковує записи всередині партиції. Query йде за ключем, Scan перебирає все, а partition key має бути висококардинальним (презентація 4, слайд 26; Практика 4 §9–10).
- Таблиця при створенні оголошує `partition_key` і опційний `sort_key` (`POST /tables`, `api/openapi.yaml`).
- Ім'я таблиці: `^[A-Za-z0-9_-]{1,64}$`, значення ключів — рядки (`design.md`).
- YCSB пише в `usertable` ключі `user<N>`.

## Options considered

| Варіант | Вердикт |
|---|---|
| `hash(table, pk)` | **Обрано** |
| `hash(table, pk, sk)` | Розкидає одну партицію по шардах, і майбутній range-запит за `sk` мусить опитати всі шарди |
| `hash(pk)` без таблиці | Однакові `pk` різних таблиць (наприклад `"1"`) завжди потрапляють на один шард, і гарячі точки корелюють |
| Range partitioning за `pk` | Монотонні ключі (serial id) заливають один шард за раз (Практика 4 §7) |

## Decision

- Ключ кільця = `f"{table}\x1f{pk}"`, хеш і vnodes — за ADR-0006.
- `\x1f` (ASCII Unit Separator) недопустимий в імені таблиці, тому межа однозначна: різні пари `(table, pk)` не дають однакового рядка.
- `sk` у хеш не входить. Він потрібен тоді й лише тоді, коли таблиця має `sort_key`, і адресує item уже всередині шарда.
- READ / EXISTS / DELETE завжди вимагають `pk`.

## Consequences

- Плюс: range-запит за `sk` у межах партиції обслуговує один шард (Практика 4 §10).
- Плюс: YCSB-ключі `user<N>` висококардинальні й розподіляються рівномірно (`docs/m2/evidence/ring/distribution.txt`).
- Мінус: гарячий partition key спрямовує весь свій трафік на один шард (hot partition: презентація 4, слайд 25; Практика 4 §6). У M2 цього не пом'якшуємо. Репліки M3 розподілять лише читання: гарячий ключ на запис усе одно б'є в одного лідера.
- Мінус: велика партиція (багато `sk`) не ділиться між шардами.
- Мінус: запит без `pk` неможливий, бо scatter-gather Scan не реалізований (Практика 4 §9).
