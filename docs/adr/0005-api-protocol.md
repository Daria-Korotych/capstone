# ADR-0005: Протокол і формат API — REST + JSON, контракт OpenAPI 3.1

Status: Accepted

**Рішення коротко:** REST + JSON за контрактом `api/openapi.yaml` (OpenAPI 3.1) на обох хопах: клієнт → coordinator і coordinator → шард.

## Context

- Курс вимагає ADR про протокол API раніше за код (`design.md`, Context).
- Клієнти API: YCSB через власний Java binding, curl на захисті, тести контракту.
- У M2 рівно один внутрішній хоп (coordinator → шард), і вартість серіалізації на ньому не виміряна.
- Стек: Python 3.12 + FastAPI, один образ з ролями `coordinator` і `shard` (`design.md`).

## Options considered

| Варіант | Вердикт |
|---|---|
| REST + JSON + OpenAPI 3.1 | **Обрано** |
| gRPC скрізь | YCSB binding потребує згенерованого protobuf-клієнта; для дебагу потрібен окремий інструмент (grpcurl) і `.proto` |
| GraphQL | Довільні вибірки полів не потрібні: кожна операція йде за ключем |
| `PUT` на колекцію `/items` з ключами в тілі | Не REST: `PUT` адресує сам ресурс (RFC 9110), а не колекцію |
| REST назовні + gRPC усередині | Аргумент лектора (дешевша серіалізація, Практика 5 §6) справедливий, але в M2 один внутрішній хоп без виміряного оверхеду, а два протоколи — це два контракти. Переглянути з числами бенчмарку M3 |

## Decision

| Операція | Метод і шлях | Семантика |
|---|---|---|
| CREATE | `PUT /tables/{table}/items/{pk}?sk=` | Тіло = item. Upsert за ключем зі шляху: `201` новий, `200` замінено |
| READ | `GET /tables/{table}/items/{pk}?sk=` | `200` + item або `404` |
| EXISTS | `HEAD /tables/{table}/items/{pk}?sk=` | `200` / `404` без тіла |
| DELETE | `DELETE /tables/{table}/items/{pk}?sk=` | За ключем |

- `PUT` замінює цільовий ресурс (RFC 9110), тому шлях у нього той самий, що в GET/HEAD/DELETE. Ключ береться зі шляху; якщо ключові атрибути є і в тілі, вони мусять збігатися зі шляхом, інакше `400`.
- `api/openapi.yaml` — рукописне джерело правди; валідатор `openapi-spec-validator`.
- FastAPI генерує власну схему; тест контракту порівнює її з `api/openapi.yaml`.
- Coordinator → шард — теж HTTP + JSON: той самий образ і той самий стек FastAPI.

## Consequences

- Плюс: будь-який HTTP-клієнт (YCSB, curl) працює без кодогенерації.
- Плюс: розбіжність коду й контракту ловить тест, а не клієнт.
- Плюс: ідемпотентність дає upsert за ключем: повтор приводить до того самого стану (Лекція 5 §19). Вибір `PUT`, а не `POST`, додає ще одне: клієнти й проксі можуть самі повторювати ідемпотентні методи, і ретраї M3 не створять дублікатів.
- Мінус: JSON текстовий, а запит серіалізується двічі (клієнт → coordinator → шард). Ціну покаже бенчмарк M2.
- Мінус: опублікований контракт стає frozen API (Практика 5 §6), тож зміни йдуть через `info.version`.
