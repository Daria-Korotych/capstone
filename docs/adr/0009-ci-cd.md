# ADR-0009: CI/CD — GitHub Actions, один образ на коміт, деплой через CloudFormation

Status: Accepted

**Рішення коротко:** trunk-based GitHub Actions. Кожен коміт у `main` збирає один образ у GHCR із тегом SHA. Деплой — оновлення стеку `kv-app` з `ImageTag=<sha>`, що замінює інстанси.

## Context

- Курс: одна основна гілка, образ тегується хешем коміту, і той самий образ іде в усі середовища (Практика 5 §4). Build → release → run суворо розділені (Практика 5 §12).
- Пісочниця: `iam:CreateRole` заборонено (`docs/m1/labrole.md`), тож немає ні OIDC-ролі для CI, ні service role, ні instance profile. Креденшели тимчасові й змінюються щосесії.
- Проби (`docs/m2/probes.md`): P2 — зміна launch template замінює інстанс; P3 — інстанс без креденшелів тягне публічний образ із GHCR.

## Options considered

| Варіант | Вердикт |
|---|---|
| GitHub Actions + GHCR + CloudFormation | **Обрано** |
| CodePipeline / CodeBuild | Потрібна service role, а `iam:CreateRole` заборонено |
| ECR замість GHCR | Інстанс без instance profile не автентифікується до приватного ECR, а роль не створити |
| OIDC замість ключів у secrets | Потрібні IAM-роль і OIDC provider, що теж заборонено |
| Деплой по SSH (`docker pull` на хості) | Невідтворюваний: зміна поза стеком, drift (анти-ціль M1) |
| Гілка на середовище (Git Flow) | Кожне середовище отримує окрему збірку, тобто інший артефакт (Практика 5 §4) |

## Decision

1. PR → lint і тести.
2. Push у `main` → `ghcr.io/…:<sha>`. Образ публічний (P3); GHCR створює пакет приватним, тож після першого push його один раз вручну перемикають на public. Тег `latest` не деплоїться.
3. Deploy-job, крок 1: `aws sts get-caller-identity`. Протухлі креденшели валять job одразу з чітким повідомленням.
4. `aws cloudformation deploy` стеку `kv-app` з `ImageTag=<sha>`, `OperatorCidr` (GitHub variable `OPERATOR_CIDR`) і `CiCidr` (`/32` раннера) → нова версія launch template → заміна інстансів (P2).
5. Smoke-тест із раннера: `GET /health` coordinator → 200.

- `scripts/push-session-creds.sh` на початку кожної сесії оновлює secrets `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN` і variable `OPERATOR_CIDR` (поточна IP оператора `/32`).

## Consequences

- Плюс: усюди той самий артефакт, а відкат — це деплой старішого SHA.
- Мінус: деплой працює лише всередині живої сесії й після ручного запуску `push-session-creds.sh`.
- Мінус: заміна — create-before-delete (P2: новий інстанс створено раніше, ніж видалено старий), тож простою інстанса немає. Ціна інша: втрачаються дані в пам'яті (очікувано до M3, `design.md`, Risks), шарди мають вікно до повторної реєстрації (≤ 15 с heartbeat), і всі IP нові (ADR-0008).
- Мінус: образ публічний, тож жодних секретів в образі.
- Ризик обмежений: сесійні ключі в GitHub secrets живуть лише до кінця сесії.
